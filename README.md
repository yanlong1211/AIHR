# AI 招聘提效台

本 Demo 面向 团队招聘场景，用于演示企业微信群消息、AI 结构化抽取、候选人台账和腾讯在线文档协作之间的自动化闭环。页面中的企业信息仅用于本次作业演示。

这是一个可直接运行的 AI 招聘提效 Demo，用于演示“企业微信群消息 → AI 结构化抽取 → 候选人台账 → 招聘看板”的闭环，界面以模拟团队招聘作为示例语境。

分享给其他使用者时，请先阅读 [操作说明](操作说明.md)，其中包含安装、配置、启动、演示流程和常见问题。

## 从 GitHub 使用

仓库中只保留 `.env.example` 配置模板，不包含真实 API Key。使用者复制模板后填写自己的 Key：

```powershell
Copy-Item .env.example .env.local
node server.js
```

## Demo 运行

无需安装依赖。在当前目录运行：

```bash
node server.js
```

打开 `http://localhost:4173` 即可预览。服务器会把 Demo 数据保存到本地 `.hireflow-data.json`，刷新页面后数据仍然存在；该文件已加入 `.gitignore`。

也可以在项目根目录的 `.env.local` 中配置兼容 OpenAI API 的模型。该文件不会提交到 Git；未配置 Key 时自动使用可解释的规则兜底：

```dotenv
LLM_API_KEY=sk-你的密钥
LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=deepseek-chat
LLM_PROVIDER=deepseek
USE_MOCK_AI=false
```

保存后重启服务：

```powershell
node server.js
```

也支持通过系统环境变量覆盖 `.env.local`，以及兼容旧配置：`DEEPSEEK_API_KEY`、`AI_BASE_URL`、`AI_API_KEY`、`AI_MODEL`。如需强制不调用大模型，可设置 `USE_MOCK_AI=true`。可访问 `/api/health` 查看当前模型、Provider 和是否已启用真实 AI。

PDF 简历上传会先在服务端校验 PDF 文件并用 Poppler `pdftotext` 提取文本；配置 `LLM_API_KEY` 后，简历关键信息提取和岗位匹配会优先调用 DeepSeek `deepseek-chat`，只有未配置 Key 或模型调用失败时才使用规则兜底，页面会明确显示实际模式。无法确认姓名、文本为空或匹配度低时，只展示结果并要求 HR 确认，不会直接写入候选人台账。扫描图片型 PDF 需要先 OCR；服务端可通过 `PDFTOTEXT_PATH` 指定 `pdftotext` 的完整路径。

## 现场演示路径

1. 点击右上角“同步群聊”，模拟从 3 个招聘群读取消息，经抽取、去重后写入持久化台账。
2. 在“AI 消息中心”输入一条或多条群消息，点击“AI 提取并入库”，展示候选人、岗位、阶段、下一步、来源群与置信度。
3. 刷新页面或点击右上角刷新，确认候选人台账和看板仍由服务端数据驱动。
4. 在台账或首页点击“导出招聘数据”，可选择导出在招候选人、指定岗位、今天更新、已录用、当前筛选结果或全部候选人 CSV。
5. 重复提交同一条消息，系统会按消息内容和招聘群去重，不重复创建候选人。

## 方案落地

### 1. 目标

把 HR 在企业微信、企业微信群、腾讯在线文档之间反复复制、记录、跟进的动作，收敛为一条自动化链路：

```text
企业微信群消息
      ↓
消息接入与去重
      ↓
大模型抽取招聘事件 JSON
      ↓
字段校验 / 候选人匹配 / 状态判断
      ↓
腾讯在线文档台账 + 招聘看板
      ↓
企业微信提醒与日报
```

### 2. Demo 已实现能力

| 能力 | 实现 |
| --- | --- |
| 群聊同步 | `POST /api/sync` 模拟读取多群消息，进入同一处理链路 |
| 企业微信回调 | `POST /api/webhook/wecom` 接收 `{ "groupName": "技术招聘群", "text": { "content": "..." } }` |
| 岗位管理 | `GET/POST /api/positions`、`PUT/DELETE /api/positions/:id`，支持岗位名称、部门、负责人、状态、编制、截止日期和备注 |
| PDF 简历匹配 | `POST /api/resumes/match` 提取文本并匹配目标岗位，`POST /api/resumes/apply` 将确认结果写入候选人台账 |
| AI 抽取 | `server.js` 支持兼容 OpenAI API 的模型；无 Key 时使用规则兜底 |
| 去重 | 对“来源群 + 原始消息”做 SHA-1 唯一键，重复提交不会重复入库 |
| 台账 | 候选人、阶段、下一步、来源群、置信度、更新时间持久化到本地 JSON |
| 可视化 | 看板 KPI、趋势、漏斗、同步记录、可搜索候选人表格均从 API 状态渲染 |
| 交付 | `GET /api/export.csv?scope=active` 导出在招台账；支持 `position`、`today`、`hired`、`filtered`、`all` 范围，适合继续上传腾讯在线文档 |
| 动态指标 | 待跟进数、面试转化率、本周候选人数量和节省录入时长随台账实时更新 |
| 人工确认 | 低置信度群消息和低分简历先进入待确认队列；HR 可编辑姓名、岗位、阶段和下一步后确认入账，或填写原因驳回归档 |

页面每 8 秒拉取一次 `/api/state`，服务端收到新回调后，打开中的招聘看板会自动刷新。真实部署时，企业微信应用回调先做签名校验，再把文本转发到 `/api/webhook/wecom`；腾讯在线文档可由同一处理函数调用文档 API 写入，当前 Demo 用 CSV 导出模拟这一写入适配层。

岗位管理页支持新建、编辑、删除、搜索和状态切换。岗位名称与 AI 抽取出的候选人岗位匹配后会自动关联；编辑岗位名称会同步关联候选人，删除岗位会解除关联并将候选人保留为“待确认岗位”。已关闭岗位禁止新增候选人，但不影响已有候选人的后续状态维护。

AI 消息中心支持上传不超过 8MB 的文本型 PDF 简历。服务端使用系统 `pdftotext` 提取文本，再把简历原文和目标岗位信息发送给 DeepSeek，提取姓名、联系方式、工作年限、技能和匹配依据；模型不可用时才回退到规则匹配。扫描图片型 PDF 当前会提示先做 OCR。低于 65 分、缺少姓名/岗位或被模型标记为需确认的消息和简历不会直接写入正式候选人台账；HR 在“待人工确认”中点击“确认入账”，补全或修正关键字段后才会写入，点击“驳回”则记录原因并归档。当前配置遵循 DeepSeek 官方兼容接口：Base URL 为 `https://api.deepseek.com`，请求地址为 `/chat/completions`。

### 3. 最小成本生产方案

| 层级 | 建议实现 | 作用 |
| --- | --- | --- |
| 消息接入 | 企业微信群机器人 / 企业微信应用回调 | 接收群聊中的文本消息，保留群 ID、发送人、时间、消息 ID |
| AI 处理 | 兼容 OpenAI API 的低成本模型，或腾讯混元轻量模型 | 将自然语言转为固定 JSON 字段，并识别招聘阶段与下一步动作 |
| 自动化编排 | n8n 自托管，或腾讯云函数 + API 网关 | 做鉴权、去重、重试、字段校验、写表和通知 |
| 数据存储 | 腾讯在线文档智能表格作为第一版主数据源 | HR 可直接查看、筛选和协作，减少新系统培训成本 |
| 可视化 | 腾讯文档仪表盘，或本 Demo 对应的轻量 Web 看板 | 展示漏斗、来源、转化率、待跟进和处理时效 |
| 低置信度处理 | 企业微信“待确认”提醒 | 缺少姓名、岗位或阶段时交给 HR 一键确认 |

第一版不需要训练模型。通过结构化提示词、字段枚举、示例消息和置信度阈值即可覆盖高频招聘话术；后续再用已确认的数据优化提示词或做轻量微调。

### 4. AI 输出结构

```json
{
  "candidate_name": "王思远",
  "position": "后端开发",
  "stage": "待安排面试",
  "next_action": "安排技术一面",
  "interview_time": "2026-09-24 14:00",
  "salary_expectation": null,
  "source_group": "技术招聘群",
  "source_message_id": "wx_msg_xxx",
  "confidence": 0.96
}
```

建议把 `source_message_id` 做唯一键，避免群消息重复触发；把 `confidence < 0.8` 或必填字段缺失的记录放入待确认队列。

### 5. 预期收益指标

上线两周后可用以下指标验收：

- 招聘消息自动入表率 ≥ 85%
- AI 抽取字段一次正确率 ≥ 90%
- HR 手动录入时长下降 ≥ 60%
- 群消息到台账的同步延迟 ≤ 2 分钟
- 逾期跟进任务数量下降 ≥ 30%

## 生产化迭代

第一阶段先覆盖文本消息和四个核心字段，跑通一个招聘群；第二阶段增加图片简历 OCR、候选人去重、自动提醒与日报；第三阶段再接入职位需求、面试反馈和 Offer 审批，形成完整招聘流程数据资产。

生产环境需要补充企业微信回调验签、接口密钥管理、个人信息最小化存储、访问权限和操作日志。Demo 本身只用于展示交互闭环，不连接真实企业微信或腾讯文档。
